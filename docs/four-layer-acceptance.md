# Four-layer boards below 500 components

This campaign makes the product goal measurable: complete representative
four-layer circuit workflows with fewer than 500 populated physical parts,
then use the evidence to identify and fix the next product gaps. It continues
PR #39 from `7a84b621`; it is not a claim that every arbitrary 499-part design
is already supported or qualified.

## Acceptance contract

Each case starts from a fresh circuit directory and records its exact spec,
runtime, workflow options and artifact hashes. The component limit counts the
complete assembly manifest, including generated bypass and strap components.
Record pin/pad counts, net counts, board area and package mix alongside part
count; a part count alone does not describe routing difficulty.

The CAD workflow must demonstrate all of the following:

1. Compile the complete assembly and satisfy independent authored pin/net
   contracts. Identify inaccessible symbols, footprints and model files.
2. Generate the schematic and native board with the explicit physical copper
   order F.Cu / In1.Cu / In2.Cu / B.Cu. Preserve pad-net identity and authored
   board constraints through save/reload and placement.
3. Review component grouping, spacing, references and mechanical restrictions.
   Placement or rendering success does not imply routing success.
4. Prepare the selected ground-plane layers, route, import the session, refill
   and verify saved native copper. Require positive filled area, no floating
   islands, native anchors and no pending plane-net pad attachments.
5. Require complete routing and zero blocking native DRC findings. Record
   warnings, routes, vias, layer use, runtime and actual supervised memory
   separately; a helper exiting successfully is insufficient evidence.
6. Produce the assembled SVG from the accepted native board and account for
   every populated component with a resolved actual model.

Electrical function, timing, controlled impedance, thermal limits and RF
performance have separate evidence states. They remain unverified without an
authored requirement and an appropriate independent analysis or measurement.
A completed CAD workflow does not silently pass those gates.

## Circuit series

The executable corpus is in
[`benchmarks/four_layer_acceptance`](../benchmarks/four_layer_acceptance/README.md).
It includes a compact connected IoT controller, an inner-plane bootstrap case
without plated ground anchors, serialized industrial outputs, filtered DAC
setpoints, a fieldbus gateway and precision acquisition. A retained SDR clock
carrier supplies a clearly labelled comparison. Measured counts and outcomes
belong to each run; planning targets never replace measured manifest counts.

Most cases reserve In1.Cu for GND and leave In2.Cu available to the router. A
dual-inner-GND control exposes that different allocation explicitly. This
selects copper count/order and zone placement; dielectric materials and
thicknesses are not qualified by the benchmark.

Fixtures declare a 0.127 mm clearance / 0.2 mm minimum-drill prototype profile.
The first IoT trial demonstrated that the implicit 0.2 mm clearance conflicted
with its stock USB-C pad geometry. These explicit review assumptions are used
only where the source does not own board rules; the native builder continues
to reject attempts to override authored rules. They are not fabrication
approval or a claim about a manufacturer's process.

Run the inexpensive checks first:

```text
python benchmarks/four_layer_acceptance/run_acceptance.py --output <new-results-directory>
```

Native execution is opt-in with `--through preview`; select one `--case` at a
time under the owned-process memory supervisor. Preserve every failed run and
use a new output directory for every retry. Do not run native cases in parallel
on the constrained validation host. Native jobs retain the 2 GiB free-RAM floor
and 2.5 GiB job cap; smaller pure Python checks use their separate bounded
profile. A memory stop is a resource outcome, not a circuit pass or failure.

The runner defaults to source mode. Use `--engine-mode installed` with an
explicit fresh-install Python to test a wheel; that mode rejects a checkout
source import and records the actual runtime path. It still loads the benchmark
corpus from the repository. Keep that corpus and runner snapshot with the run.

For independent Python validation without native subprocesses, call
`circuit_weaver.dispatcher.validate_design` with `enrich_parts=False`,
`use_kicad=False` and `check_native_export=False`. The last option explicitly
controls native schematic SVG export; `use_kicad=False` alone only controls
library resolution. Generated-text, presentation and requested determinism
checks still run, while report metadata marks native export as not run. Native
workflow trials retain the default export check and native resource profile.

## Fault detection and gap reports

Positive designs are accompanied by deliberate wrong-net, unavailable-library,
wrong-layer and incomplete-limit controls. Record the mutated input, validator
response and original-input preservation. A declared but unexecuted control is
unverified; a missed fault remains a gap.

Keep preflight, CAD completion and product qualification separate in the final
report. For each gap record the affected case, failed or absent gate, exact
evidence, reproduction command and next action. Prioritize failures of valid
inputs and missed bad-input controls over cosmetic improvements. Include
resource interruptions and unsupported package/analysis classes explicitly.

The preceding 438-part DAC comparison established native four-layer planes,
but both matched routes stopped at the host RAM reserve. The new campaign must
extend that evidence; it cannot count those interrupted routes as accepted
boards or use them to claim improved routed copper.

## Initial local checks, October 24

The first corrected non-native sweep compiled and validated all ten cases,
checked their authored endpoint contracts and resolved the 21 distinct local
footprints and referenced model files. It took 23.554 seconds, peaking at
61,349,888 bytes of committed job memory, with no KiCad child process. File
access is separate from native model rendering and device qualification.

| Case | Measured populated physical parts |
| --- | ---: |
| IoT environment controller | 25 |
| IoT controller without plated GND anchors | 25 |
| 8-channel relay output | 36 |
| 48-channel relay output | 96 |
| 288-channel relay output | 466 |
| 24-channel filtered setpoint | 168 |
| 80-channel filtered setpoint | 482 |
| Fieldbus gateway | 187 |
| Precision acquisition | 145 |
| SDR clock-carrier comparison | 236 |

All ten seed layouts fit their unchanged outlines with independently checked
envelope bounds and nonoverlap. Three cases required reducing the extra
seed-layout gap from 3 to 1.5 mm; board rules and final native DRC remain
unchanged. This is an initial packing result, not final native placement.

The native IoT candidate passed an independent KiCad DRC with zero blockers.
The trials exposed repeated USB-C shield-pad handling, internal via-layer
contacts, plated connector-pad transitions and enabled-versus-known layer
inventory gaps. Those checks have targeted regressions; completed native
publication and model rendering must still be demonstrated by per-run proof.
The broader 96–482-part native routing campaign remains an acceptance gate.
